# Changelog

## Unreleased

- Milestone 0, repo scaffolding and CI: `package.json`, TypeScript build to `dist/`, a CLI stub that answers `--version` and `--help` and exits 2 on an unknown flag, tests with `node:test`, the text hygiene check (`scripts/check-text.mjs`), the pack smoke test (`scripts/pack-smoke.mjs`), an eval placeholder, the MIT license, and a CI workflow for Linux, Windows and macOS with Node 22 and 24.
- Milestone 1, normalized model and adapter interface: the normalized test model (`src/model/types.ts`) with its JSON Schema (`schemas/model.schema.json`), the language adapter interface and registry, the rule and report types, and capability gating: a rule runs on a file only when the file has every capability the rule requires, and a skipped rule is listed with the reason. A toy adapter in the tests proves the interface end to end without a parser. Adds the golden file test helper (`UPDATE_GOLDEN=1 npm test`).
- Milestone 2, tree-sitter runtime and grammars: the parser service (`web-tree-sitter`, WebAssembly, loaded on first use and cached), vendored grammars for JavaScript, TypeScript, TSX, Python and Java with a manifest (version, license, ABI, sha256) and their license texts, asset loading through `src/assets.ts`, 1-based positions on LF-normalized text, and the lexical scanner used as the fallback when a grammar is unavailable or more than 30% of a file is unparseable. Adds `docs/adapters.md` and `scripts/build-grammars.mjs`.
- Milestone 3a, config and glob helper: config loading from JSON or YAML (`qa-core-review.config.json`, `.yaml`, `.yml`, `.qa-core-review.json`, `.qa-core-review.yaml` or a `qa-core-review` key in `package.json`, searched from the root upward to the git root), `schemas/config.schema.json`, defaults for every key, and errors that name the file, the JSON pointer and the problem. YAML is parsed as plain data only: custom tags are rejected. Adds the glob helper (`**`, `*`, `?`, `{a,b}`, Windows-style input paths) and a byte order mark check in the text lint.
- Milestone 3b, project detection and discovery: the `detect` command (`--format pretty|json`, `--root`, `--config`) shows the projects found, their frameworks with the evidence for each, and the test files per adapter. Detection reads manifests only (`package.json` and runner config files, Python requirement and project files, `pom.xml` and Gradle build files) and never runs a build tool. In a monorepo each file belongs to the nearest project for its language, config `projects` entries override detection, and files in languages with no static adapter yet (Scala, Rust, Go and others) are listed under the generic adapter. An invalid config exits 2 with the file and the JSON pointer. Adds `schemas/detect.schema.json` and the fixture projects.
- Milestone 4a, JS/TS adapter structure: the `js` adapter reads tests, suites and hooks from JavaScript, TypeScript, JSX and TSX files for Playwright, Cypress, Jest, Vitest, Mocha, WebdriverIO and node:test. It extracts full titles, modifiers (`only`, `skip`, `fixme`, `todo`, `fail`, `concurrent`, `serial`), skips with their reason, `.each` tables and tests made in loops, 1-based spans, a body hash, imports and suppression comments, and it decides the runner of each file from its imports and globals before falling back to the project. Adds golden models for every framework and the shared adapter test helpers.
- Milestone 4b, JS/TS adapter assertions: the `js` adapter now reads what each test checks. It finds assertions written with `expect` (Jest, Vitest, Playwright, jest-dom, expect-webdriverio), Chai (`expect`, `should`, `assert`), node's `assert`, Sinon and Cypress `should`, with their kind, both operands (literal, locator, count, mock), and whether each one is negated, soft, finished, awaited, conditional or unreachable. It also reads `expect.assertions` guards, expected errors, `try`/`catch` blocks and promise `catch` handlers, and it counts calls to helper functions, page object methods and custom Cypress commands that contain an assertion. Adds `createHelperIndex` and the adapter's `collectHelpers`.
- Milestone 4c, JS/TS adapter body facts: the `js` adapter now also reads what each test does. It finds fixed sleeps and condition waits, selectors with their strategy and positional picks, steps, HTTP data operations, module, function and network mocks, the module under test, and the resources a test takes (spies, fake timers, globals, env values, browsers, contexts, pages) with whether they are released. A file that cannot be parsed is read by the lexical scanner, which still finds tests, focus and skip markers, assertions and sleeps. The adapter now fills every capability of the model. Adds `selectorStrategy` and the JS/TS section of `docs/adapters.md`.
- Milestone 5a, engine and `review` command: `qa-core-review review [paths...]` (also the default command) finds the test files, builds the helper index of each project, runs the rules each file supports and writes `.qa-core/review/report.json` (`schemas/report.schema.json`, version 2). Findings have a fingerprint with no line number in it, each test gets a verdict (pass, review or fail), and the exit code is 0, 1, 2 or 3 as documented. Flags: `--fail-on`, `--rules`, `--disable`, `--language`, `--framework`, `--format`, `--stdout json`, `--output`, `--dump-model`, `--root`, `--config`. The first rule is `QCR-X001` (a file that cannot be parsed, or a test file with no test in it). The text output is the summary only for now.
- Milestone 5b, text output and commands: `review` now prints the full text view: a header, one block per test (fail, then review, then pass) with each finding's rule, place, message, evidence and fix, then the findings about whole files, the summary and a line per language. New flags: `--quiet`, `--no-color` (also `NO_COLOR`), `--max-findings`. New commands: `rules`, `explain <ruleId>`, `adapters` and `init --config [json|yaml]`.
- Milestone 6, assertion rules: `QCR-A001` no-assertion, `QCR-A002` trivial-assertion, `QCR-A003` cannot-fail-assertion (not finished, never reached, not awaited, locator truthiness, a count of at least zero, a truthy list literal) and `QCR-A004` conditional-assertion, for JS/TS. Each finding has a fix and a good example in the language of the file, and `explain` prints the bad and good examples. `docs/rules.md` documents the rules. The helper index now also reads the local files a test file imports (two steps deep) and the Cypress support files, so a page object outside the test folders counts. Assertions have a new optional `operator` field for comparisons. A callback that calls `done()` or a promise's `resolve` no longer makes its assertions conditional.
